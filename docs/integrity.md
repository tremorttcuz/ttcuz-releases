# Проверка целостности ttcuz 0.6.7.8

Установленный универсальный APK проходит полную проверку один раз. Успешный результат сохраняется в приватных настройках и используется при следующих запусках той же установленной сборки. Идентификатор включает пакет, versionCode, время обновления, путь, размер и время изменения APK, сертификат и открытый ключ автора. После обновления или изменения APK проверка выполняется один раз заново. Ошибки и отрицательные результаты не кешируются.

Во время первой проверки экран с MD3-индикатором открывается поверх исходного экрана после его onResume. Исходный экран, задача и Intent не завершаются и не пересоздаются. При успехе закрывается только экран проверки; кнопка «Назад» не открывает непроверенное приложение. Ошибка чтения или записи кеша не превращает успешно проверенную сборку в подменённую.

Проверяются текущий сертификат подписи APK, имя пакета и все файлы: DEX, нативные библиотеки, манифест, таблица ресурсов, картинки, шрифты и другие assets. Удалённые, добавленные и повторяющиеся файлы отвергаются. Служебные файлы подписей APK и два файла самой печати исключены из списка, чтобы избежать циклического хеша. Список хешей заверен отдельным ключом RSA 3072/SHA-256; проверяющий открытый ключ встроен в приложение. Подмена списка без этого закрытого ключа не проходит проверку.

При обнаруженной подмене показывается: «Мы просили вас не делать форк этого мода. Пожалуйста, удалите текущую версию». Вход остаётся заблокированным. Ошибка чтения отличается от подмены и предлагает повторить проверку. Отключённые системные анимации учитываются.

Проверка не отправляет данные на сервер и не удаляет файлы пользователя. Первое полное чтение APK на медленном накопителе может занять несколько секунд или дольше. Повторные запуски используют сохранённый результат и не хешируют содержимое APK. На физическом телефоне поведение этой правки ещё не проверено.

Это защита от подмены и простой перепаковки, а не доказательство отсутствия форков. Изменив исходники, можно удалить проверку или заменить открытый ключ. Стандартный отладочный сертификат APK сам по себе не является секретом; отдельный ключ печати защищает список содержимого. Невырезаемой проверки на чужом устройстве нет.

## Сборка владельцем

Закрытый ключ хранится вне проекта в `%USERPROFILE%/.ttcuz/integrity.p12`, пароль — в отдельном локальном файле. Не включайте эти файлы, пароль и ключ подписи APK в Git, ZIP или приложение. Сохраните личную резервную копию: без исходного ключа новую печать с прежним открытым ключом выпустить нельзя.

Перед сборкой задайте `TTCUZ_INTEGRITY_KEY` (путь к своему PKCS12, необязательно для стандартного пути) и `TTCUZ_INTEGRITY_PASSWORD` (его пароль). В PKCS12 используется alias `ttcuz-integrity`; открытый ключ должен совпадать с `IntegrityKey.java`. Укажите `--keystore` для сертификата APK и сохраните прежний ключ для обновления установленного приложения.

Сборщик проверяет ключ заранее, после формирования APK подписывает весь список файлов, затем выравнивает и подписывает APK. Приватный ключ не считывается приложением; в APK включаются только список хешей и его подпись.
