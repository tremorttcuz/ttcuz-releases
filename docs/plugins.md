# Плагины ttcuz — полное руководство

Всё, что нужно, чтобы написать, собрать, проверить и выложить плагин для ttcuz (мод TikTok **47.7.3**; плагины, написанные для 47.2.41, тоже ставятся). Версия Plugin API — **4** (события TikTok, плеер, автоматизация, селекторы, общение плагинов); плагины API 1, 2 и 3 продолжают работать без изменений.

> Это руководство — единственный актуальный источник. Его же в виде одного файла читают ИИ-ассистенты: `https://ttcuz.ttcuz1337.workers.dev/plugin-api.md` (оглавление для них — `/llms.txt`).

## 1. Что такое плагин

Плагин — это Java-класс, который наследует `cat.ttcuz.framework.plugin.TtcuzPlugin` и переопределяет только нужные ему методы-хуки. Мод вызывает хуки, когда в TikTok что-то происходит: открылся экран, пришла страница ленты, рисуется текст, сменился аккаунт. Через `ttcuz()` плагин получает всё, что даёт мод: настройки, окна, сеть, разрешения Android и другое.

Что плагин может:

- добавлять свои кнопки, панели и окна поверх любого экрана TikTok и менять его элементы;
- менять тексты, ники, цвета и регион, который видит TikTok;
- убирать или переставлять видео в ленте;
- ходить в интернет, показывать уведомления, сохранять файлы в «Загрузки»;
- с разрешения пользователя пользоваться камерой, микрофоном, местоположением, контактами и т. д.;
- иметь свою страницу настроек в моде.

Чего плагин не может:

- объявить свою Activity, Service или BroadcastReceiver: Android читает их из манифеста приложения при установке, а плагин появляется позже. Вместо этого — свои view поверх существующих экранов и окна мода;
- получить разрешение Android, которого нет в манифесте приложения (список — в [разделе 12](#12-разрешения-android));
- перехватывать произвольные методы TikTok: на Android нет способа подменить чужой метод без нативного фреймворка перехвата, а его в моде нет. Хуков ровно столько, сколько в этом руководстве; события API 4 (`onTikTok`) закрывают самые частые случаи, а остальное достаётся через рефлексию (`tiktok`, раздел 15). Подробно — в [разделе 18.5](#185-чего-нет-в-api-4-и-почему).

> **Безопасность.** Песочницы нет и быть не может: плагин работает внутри TikTok со всеми его правами. Разрешения из manifest.json — это обещание, которое проверяет мод (вызов без разрешения не сработает), и список, который пользователь видит под кнопкой с ключом. Ставьте только то, что прочитали сами или взяли из магазина: там каждый плагин проверен.

---

> **Свои островки — не плагины.** Нижнюю панель TikTok можно целиком заменить своим Java-классом без разрешений и без `manifest.json`: это отдельный формат, у него своё руководство — [islands.md](islands.md).

## 2. Как собрать: три способа

| Способ | Что нужно | Подробно |
|---|---|---|
| **Прямо в приложении** | только телефон | Настройки ttcuz → Плагины → **Редактор плагинов** |
| **Termux** на телефоне | Termux из F-Droid | [termux.md](termux.md) |
| **Компьютер** | JDK 17+ и Python 3 | [pc.md](pc.md) |

### В приложении

1. **Настройки ttcuz → Плагины → Редактор плагинов.**
2. Заполните «О плагине»: название, ID, версию, авторов (ники через запятую), главный класс, описание.
3. Отметьте **разрешения** — всё, чем пользуется плагин.
4. Пишите код во вкладках файлов (долгое нажатие на файл — удалить). Чтобы открыть готовый проект, нажмите **Открыть ZIP** (подойдёт и «Download ZIP» с GitHub).
5. Добавьте **картинку**: она обрежется в квадрат 128×128.
6. **Собрать и установить** — плагин компилируется на самом телефоне и сразу ставится. Первая сборка один раз скачивает компилятор (ECJ и D8, около 8 МБ, из релиза `tools-1` мода) и `android.jar` с серверов Google (25 МБ). Мод проверяет размер и SHA-256 каждого файла.
7. Ошибка компиляции открывается окном с номером строки и кнопкой «Скопировать».

Черновик сохраняется сам. **Экспорт ZIP** сохраняет исходники в файл.

### В Termux или на компьютере

```sh
ttcuz-plugin new my-plugin          # Termux: заготовка в «Загрузках»
ttcuz-plugin ~/storage/downloads/my-plugin
# или на компьютере:
python3 -m ttcuz.plugin my-plugin -o my-plugin.ctt
```

Готовый `.ctt` ставится в моде: **Настройки ttcuz → Плагины → Установить .ctt**.

## 3. Первый плагин за пять минут

**manifest.json**

```json
{
  "id": "com.me.hello",
  "name": "Hello",
  "name_ru": "Привет",
  "version": "1.0",
  "author": "me",
  "description_ru": "Здоровается при запуске.",
  "entry": "com.me.hello.Main",
  "api": 4,
  "tiktok": "47.7.3",
  "permissions": []
}
```

**java/com/me/hello/Main.java**

```java
package com.me.hello;

import cat.ttcuz.framework.plugin.PluginSettings;
import cat.ttcuz.framework.plugin.TtcuzPlugin;

public final class Main extends TtcuzPlugin {
    @Override
    public void onStart() {
        int starts = ttcuz().prefs().getInt("starts", 0) + 1;
        ttcuz().prefs().edit().putInt("starts", starts).apply();
        if (ttcuz().prefs().getBoolean("greet", true)) ttcuz().toast("Привет! Запуск №" + starts);
    }

    @Override
    public void onSettings(PluginSettings s) {
        s.toggle("greet", "Здороваться при запуске", true);
    }
}
```

Соберите любым способом из раздела 2. Плагин без разрешений: ему ничего не нужно, кроме своих настроек и сообщения на экране.

## 4. Устройство проекта и файла .ctt

**Проект:**

```
my-plugin/
├── manifest.json
├── icon.png                необязательно: квадрат, 128×128 достаточно
└── java/
    └── com/me/hello/
        └── Main.java       путь = пакет: com.me.hello → java/com/me/hello/
```

**Файл .ctt** — обычный ZIP:

```
my-plugin.ctt
├── manifest.json   обязательно
├── classes.dex     обязательно: весь код плагина, один dex
└── icon.png        необязательно
```

Правила и ограничения:

- В `classes.dex` не должно быть классов `cat.ttcuz.framework.plugin.*`: их даёт приложение, а вторая копия под тем же именем для Android — другой класс. Сборщик их исключает сам.
- Только один dex. На компьютере и в Termux плагин собирается как Java 17, **в редакторе на телефоне — как Java 8** (без `var`, `record`, `switch`-выражений и текстовых блоков `"""`; лямбды можно). Пишите на Java 8 — тогда плагин собирается везде. D8 переводит код под Android 7+ (min-api 24).
- Сторонние `.jar` не поддерживаются: переносите нужный код исходниками в `java/`.
- `manifest.json` до 64 КБ, `icon.png` — настоящий PNG.
- Плагин, который ставится файлом, может весить до 20 МБ (classes.dex до 20 МБ). В магазин пакет уходит до 1 МБ: так хранит сервер на бесплатном тарифе.
- Файл можно назвать как угодно: мод смотрит на содержимое, а не на расширение.

## 5. manifest.json — все поля

| Поле | Обязательно | Что это |
|---|---|---|
| `id` | да | Имя плагина на диске и в настройках: латиница, цифры, `.`, `-`, `_`, начинается с буквы или цифры, до 128 символов. **По нему плагин обновляется** — не меняйте его между версиями. Удобно брать имя пакета: `com.me.hello`. |
| `entry` | да | Полное имя главного класса: `com.me.hello.Main`. Класс `public`, с конструктором без аргументов. |
| `name` | нет | Название в списке (по умолчанию `id`). |
| `name_ru`, `name_uk`, `name_en`… | нет | Название на языке телефона; если такого нет — `name`. |
| `version` | нет | Строка рядом с названием (по умолчанию `1.0`). Магазин сравнивает её с установленной и предлагает «Обновить». |
| `author` | нет | Авторы, ники через запятую: `nick1, nick2`. Показываются как `v1.0 • @nick1, @nick2`. |
| `description`, `description_ru`… | нет | Что делает плагин. В списке видны первые 4 строки, остальное — по нажатию. |
| `api` | нет | `4` — текущий API: всё из API 3 плюс `watch`, `automation`, `player`, селекторы и общение плагинов (раздел 18.3); `3` — эффекты и экраны мода; `2` — API с разрешениями; `1` — старый, без списка (по умолчанию `1`). Мод отказывается ставить плагин с API новее своего, с понятной причиной. |
| `tiktok` | нет | Для какой версии TikTok. Если указано: та, на которой стоит мод (сейчас `47.7.3`), или `47.2.41`. Редактор пишет сюда версию TikTok телефона сам. |
| `permissions` | нет | Список разрешений: `["interface", "network", "android.permission.CAMERA"]`. Начиная с API 2 нужно перечислить всё, чем пользуется плагин. До 32 элементов. |
| `uses` | нет | Зачем плагину каждое разрешение: `{"network": "скачивает цитату дня"}`. Обычно его не пишут руками — сборка собирает его из комментариев `// @uses` в коде (раздел 6.1). До 300 символов на разрешение. |

## 6. Разрешения

Плагин API 2, 3 и 4 перечисляет в `permissions` всё, что использует. Мод проверяет это в двух местах:

- **при запуске**: если плагин переопределяет хук, которому нужно разрешение, а разрешения в списке нет, плагин не запустится. В его карточке будет написано, каких разрешений не хватает;
- **при вызове**: метод `ttcuz()` без нужного разрешения бросает `SecurityException` с именем разрешения.

Пользователь видит список под кнопкой **с ключом** в карточке плагина, каждое разрешение — с иконкой и пояснением. Чувствительные (интернет, аккаунт, внутренности TikTok, разрешения Android) выделены цветом предупреждения. В магазине список виден в строке «Может: …».

| Разрешение | Что открывает | Хуки | Методы `ttcuz()` |
|---|---|---|---|
| `interface` | Свои кнопки и окна поверх экранов TikTok, изменение элементов | `onView`, `onScreen` | `overlay`, `find`, `views`; API 4: `query`, `queryOne`, `tree`, `hide`, `unhide`, `inject` |
| `text` | Тексты и ники | `onText`, `onNickname` | — |
| `feed` | Лента | `onFeed` | — |
| `colours` | Цвета приложения | `onColour` | — |
| `region` | Регион, который видит TikTok | `onRegion` | — |
| `events` | События мода и других плагинов | `onEvent` | API 4: `call` |
| `account` | id вошедшего аккаунта | `onAccountChanged` | `accountId` |
| `effects` (API 3) | Размытие, motion blur, цветовые матрицы, шейдеры AGSL поверх любых view | — | `blur`, `motionBlur`, `colourMatrix`, `shader`, `uniform`, `clearEffect` |
| `mod` (API 3) | Интерфейс и настройки самого мода, свои строки в настройках мода | `onModScreen`, `onModPanel`, `onModSettings` | `modSettings`, `modSetting`, `setModSetting`, `refreshModScreen` |
| `watch` (API 4) | Действия в TikTok: какое видео открыто, комментарии, поиск, сообщения в чате, лента, приложение на экране | `onTikTok` | — |
| `automation` (API 4) | Нажатия, жесты и ввод текста за пользователя | — | `click`, `longClick`, `tap`, `swipe`, `type` |
| `player` (API 4) | Видео на экране: пауза, воспроизведение, скорость, сохранение | — | `video`, `videoId`, `playing`, `pause`, `play`, `speed`, `saveVideo` (+`storage`) |
| `tiktok` | Скрытые методы и поля TikTok | — | `hostLoader`, `type`, `method`, `field` |
| `network` | Интернет | — | `http` |
| `notifications` | Свои уведомления | — | `notify` |
| `clipboard` | Буфер обмена | — | `copy`, `paste` |
| `storage` | Файлы в «Загрузки» | — | `saveDownload` |
| `android.permission.…` | Разрешение Android (раздел 12) | `onPermission` | `request`, `vibrate` (для `VIBRATE`) |

Без разрешений доступно: `prefs`, `accountPrefs`, `data`, `bundle`, `app`, `screen`, `accent`, `log`, `toast`, `ui`, `later`, `away`, `every`, `emit`, `expose`, `bounds`, `dp`, `palette`, `animateIn`, `animateOut`, `dialog`, `menu`, `open`, `share`, `has`, `api`, `permissions`, `can` и все хуки, не перечисленные в таблице.

### 6.1. Пометки в коде: что плагин делает с разрешением

Каждая строка, где код пользуется разрешением, помечается автоматически — и в редакторе в приложении, и при сборке на ПК. Автор пишет рядом, **зачем**, обычным комментарием:

```java
// @uses network: скачивает одну цитату с api.github.com/zen
String line = ttcuz().http("https://api.github.com/zen");

@Override
public List onFeed(List posts) { ... } // @uses feed: прячет рекламные видео
```

Правила:

- формат: `// @uses <разрешение>: <зачем>`; можно и `// @разрешение network: …`;
- комментарий ставится **над строкой** (до 4 строк выше, подряд идущие комментарии и аннотации вроде `@Override` не мешают) или **в конце той же строки**;
- для разрешений Android можно писать коротко: `// @uses CAMERA: …` = `android.permission.CAMERA`;
- несколько причин для одного разрешения склеиваются через `;` (до четырёх);
- комментарий засчитывается, даже если сканер не видит вызова (например, рефлексия) — так можно объяснить что угодно.

При сборке причины попадают в `manifest.json` как поле `uses`, и пользователь видит их под **ключом** в карточке плагина: под каждым разрешением — строка «Зачем: …». Если `uses` уже есть в манифесте, его значения важнее комментариев.

**Редактор в приложении.** Под кодом открытого файла появляется блок «Что делает код с разрешениями»: номер строки, разрешение и вызов, которому оно нужно. Строки в коде подсвечены цветом акцента, а **красным** — если разрешение не отмечено. Нажатие на строку блока:

1. разрешение не отмечено → отмечает его;
2. причины нет → вставляет над строкой `// @uses …: ` с тем же отступом и ставит курсор, остаётся дописать;
3. причина есть → переходит к строке в коде.

Для API 2–4 «Собрать и установить» и «Отправить на проверку» не запустятся, пока в коде есть красные строки, — иначе плагин упал бы уже на телефоне.

**Сборка на ПК.** `python3 -m ttcuz.plugin` печатает тот же список:

```
==> What the code does with permissions
    java/com/example/quote/Main.java:26  network  http()  [ok]
    java/com/example/quote/Main.java:29  notifications  notify()  [ok]
    why network: скачивает одну цитату с api.github.com/zen
```

`[NOT ASKED]` у плагина API 2–4 останавливает сборку с ошибкой `the code uses …, which manifest.json "permissions" does not ask for`.

Что помечается: вызовы `http`, `notify`, `copy`/`paste`, `saveDownload`, `accountId`, `hostLoader`/`type("…")`/`method("…")`/`field("…")`, `overlay`/`removeOverlay`/`find`/`views`, `vibrate`, методы API 4 через `ttcuz().` (`query`, `hide`, `tap`, `swipe`, `pause`, `speed`, `call`…), хуки из таблицы выше и любые строки `"android.permission.X"` или `Manifest.permission.X`. Комментарии сканер пропускает, а внутри строк ищет только имена разрешений Android.

**Плагины API 1** работают без списка, как раньше: им по-прежнему доступны `accountId` и рефлексия к TikTok. Под ключом для них показывается список, собранный по хукам, которые они переопределяют. Возможности API 2–4 (`overlay`, `http`, `notify`, `effects`, `mod`, `watch`, `player`…) требуют разрешения у всех плагинов.

## 7. Жизненный цикл плагина

```
установка ─▶ проверка пакета ─▶ загрузка класса ─▶ проверка разрешений
        ─▶ attach(PluginContext) ─▶ onLoad() ─▶ onStart() ─▶ onAccountChanged(uid) ─▶ onActivityResumed(текущий экран)
        ─▶ … хуки, пока плагин включён …
выключение / удаление / обновление ─▶ onStop() ─▶ ttcuz() закрыт: отложенные задачи отменены, его overlay убраны
```

- **Установка** проверяет пакет в отдельной папке и только потом подменяет старую версию. Если новая версия не запустилась, возвращается старая.
- **Обновление** — установка пакета с тем же `id`. Настройки (`prefs`, `accountPrefs`) и папка `data()` сохраняются.
- **onLoad()** вызывается один раз после загрузки, на фоновом потоке. Здесь можно подготовить данные; исключение отсюда — причина, по которой плагин не включится (она будет видна в карточке).
- **onStart() / onStop()** — плагин включён или выключен (переключатель, удаление, обновление). Вызываются на главном потоке.
- **Ошибка в любом хуке** перехватывается: TikTok не падает. Плагин помечается сломанным, останавливается, а текст ошибки показывается в его карточке и пишется в журнал мода. Чтобы запустить снова, выключите и включите его.
- **Безопасный режим** (Настройки ttcuz → Плагины → «Безопасный режим») — при старте TikTok не запускается ни один плагин. Нужен, если какой-то плагин мешает приложению открыться.

## 10. Настройки плагина

Мод строит страницу настроек плагина сам, по строкам, которые плагин описывает в `onSettings`. Кнопка с шестерёнкой в карточке плагина появляется, только если `onSettings` или `onOpenSettings` переопределены.

```java
@Override
public void onSettings(PluginSettings s) {
    s.text("Пояснение или заголовок");
    s.action("Сделать сейчас", () -> doIt());
    s.toggle("enabled", "Включено", true);                        // ключ, подпись, по умолчанию
    s.choice("mode", "Режим", new String[]{"А", "Б", "В"}, 0);     // индекс выбранного
    s.slider("size", "Размер", 10, 40, 20);                        // min, max, по умолчанию
    s.view(myView);                                                // любой свой View
}
```

| Строка | Значение в `prefs()` |
|---|---|
| `toggle(key, title, def)` | `getBoolean(key, def)` |
| `choice(key, title, options, def)` | `getInt(key, def)` — индекс |
| `slider(key, title, min, max, def)` | `getInt(key, def)` |
| `text`, `action`, `view` | не хранятся |

Ограничения: у `choice` хотя бы один вариант и `def` в пределах списка; у `slider` `min < max` и `def` между ними — иначе `IllegalArgumentException`.

Изменение любой строки вызывает `onPreferenceChanged("plugin", key)`.

**Свой экран настроек**: переопределите `onOpenSettings(Activity)`, покажите своё окно (например, `ttcuz().dialog(...)` или view через `overlay`) и верните `true`.

## 11. Интерфейс: свои кнопки и окна поверх TikTok

Нужно разрешение `interface`.

```java
@Override
public void onScreen(Activity activity, ViewGroup content) {
    if (!activity.getClass().getName().endsWith(".MainActivity")) return;
    if (button != null && button.isAttachedToWindow()) return;     // уже стоит
    TextView b = new TextView(activity);
    b.setText("★");
    b.setOnClickListener(v -> ttcuz().toast("Нажато"));
    FrameLayout.LayoutParams at = new FrameLayout.LayoutParams(ttcuz().dp(48), ttcuz().dp(48));
    at.setMargins(0, 0, ttcuz().dp(16), ttcuz().dp(140));
    b.setLayoutParams(at);
    button = ttcuz().overlay(activity, b, Gravity.BOTTOM | Gravity.END);
    ttcuz().animateIn(button);
}
```

Советы:

- **Слой плагина** лежит поверх всего экрана и не мешает касаниям: TikTok получает всё, что не попало в ваши view. У каждого плагина свой слой; при остановке плагина слой убирается.
- **Изменение элементов TikTok**: найдите их через `find` или `views` в `onScreen` и меняйте как обычные view (видимость, текст, цвет). TikTok может перезаписать изменения, когда перерисует экран: тогда повторите их в `onView` или в следующем `onScreen`.
- **Не храните Activity и view** дольше экрана: в `onActivityDestroyed` обнуляйте ссылки, иначе экран не освободится из памяти.
- **Цвета мода**: `ttcuz().accent()` и `ttcuz().palette()` — чтобы плагин выглядел как часть приложения.
- **Окна**: `ttcuz().dialog(...)` и `ttcuz().menu(...)` рисуются в стиле мода и подстраиваются под тему.

## 12. Разрешения Android

Плагин может попросить разрешение Android, только если оно:

1. есть в списке `permissions` манифеста плагина;
2. объявлено приложением. ttcuz объявляет для плагинов: `CAMERA`, `RECORD_AUDIO`, `ACCESS_COARSE_LOCATION`, `ACCESS_FINE_LOCATION`, `READ_CONTACTS`, `READ_CALENDAR`, `READ_MEDIA_IMAGES`, `READ_MEDIA_VIDEO`, `READ_MEDIA_AUDIO`, `BLUETOOTH_CONNECT`, `VIBRATE`, а также `POST_NOTIFICATIONS` и всё, что объявил сам TikTok.

Само объявление ничего не выдаёт: Android спрашивает пользователя, только когда плагин вызывает `request`.

```java
if (!ttcuz().has("android.permission.CAMERA")) {
    ttcuz().request("android.permission.CAMERA", granted -> {
        if (granted) openCamera(); else ttcuz().toast("Без камеры не получится");
    });
}
```

Ответ приходит на главный поток — в `result` и в `onPermission`. Если приложение такого разрешения не объявляет, ответ сразу будет `false`, а причина появится в журнале.

## 13. Сеть, файлы, уведомления, буфер обмена

```java
ttcuz().away(() -> {
    try {
        String json = ttcuz().http("https://example.com/data.json");                         // network
        String answer = ttcuz().http("POST", "https://example.com/api", "{\"a\":1}", null);   // JSON по умолчанию
        ttcuz().notify("Готово", "Получено " + json.length() + " символов");                  // notifications
        ttcuz().saveDownload("data.json", "application/json", json.getBytes("UTF-8"));         // storage
    } catch (java.io.IOException e) {
        ttcuz().log("сеть: " + e.getMessage());
    }
});
```

- `http` — только `https://`, таймауты 15 с, ответ до 2 МБ. Код 4xx/5xx бросает `IOException` с текстом ответа. Вызов на главном потоке бросает `IllegalStateException`.
- `notify` на Android 13+ требует `POST_NOTIFICATIONS`: попросите его через `request` (см. пример `quote-of-the-day`).
- `saveDownload` возвращает `Uri` файла. Файлы для внутреннего пользования храните в `data()`.
- `copy` и `paste`: Android отдаёт содержимое буфера, только пока TikTok на экране.

## 14. Потоки и скорость

- **Главный поток** — все хуки экранов, `onStart`/`onStop`, `ui`, `later`. Не делайте здесь сеть, тяжёлые вычисления и работу с диском: TikTok начнёт тормозить. Вынесите это в `away`.
- **Горячие пути** — `onColour`, `onView`, `onText`: они вызываются сотни раз в секунду. Ничего не создавайте (никаких `new`), не ищите view, не пишите в журнал, не обращайтесь к `prefs()` в цикле — прочитайте настройку заранее в поле.
- **`onActivityResumed`** вызывается на каждом экране — только быстрые проверки.
- **Таймеры**: `later` отменяется при остановке плагина. Не запускайте частые повторы, пока TikTok в фоне: это расходует батарею. Проверяйте `ttcuz().screen() != null`.
- **Память**: не держите `Activity`, `View` и большие `Bitmap` в статических полях.

## 15. Доступ к классам TikTok

Нужно разрешение `tiktok` (плагинам API 1 доступно без него).

```java
Class<?> type = ttcuz().type("com.ss.android.ugc.aweme.feed.model.Aweme");
java.lang.reflect.Method getDesc = ttcuz().method("com.ss.android.ugc.aweme.feed.model.Aweme", "getDesc");
String caption = (String) getDesc.invoke(post);
```

`method` и `field` ищут и в родительских классах и сразу делают член доступным.

Осторожно:

- Большинство классов TikTok названы обфусцированно (`X.0TFu`) и **меняются в каждой версии**. Плагин, завязанный на такие имена, ломается при обновлении TikTok. Опирайтесь на стабильные имена (`Aweme`, `User`, `MainActivity`) и проверяйте `null`.
- Ошибка рефлексии внутри хука остановит плагин. Оборачивайте такие места в `try/catch`.
- Магазин проверяет рефлексию к аккаунту и сессии особенно строго.

## 18. Публикация в магазин и проверка

### Отправка

В редакторе нажмите **Отправить на проверку**: плагин собирается и отправляется вместе с исходниками, картинкой и баннером. Пакет должен быть до 1 МБ.

- **Картинка** — PNG до 32 КБ или **анимированный GIF** до 96 КБ. Можно выбрать GIF или **видео**: мод (и сайт магазина) сам сделает из первых трёх секунд GIF 128×128. В списке плагинов и в магазине она анимируется.
- **Баннер** — широкая картинка 3:1 над карточкой в магазине (кнопка «Баннер» в редакторе или поле на сайте). Мод режет её до 1200×400 и сжимает в JPEG до 280 КБ.
- **Отзывы** — звёзды и текст, ответы, лайки и дизлайки отзывов работают и на сайте, и в магазине в приложении. Новая отправка того же плагина от того же автора заменяет ещё не проверенную.

### Автоматические проверки (ещё до модератора)

Код не принимается, если:

- **он запутан (обфусцирован)**:
  - большинство имён из одной-двух букв;
  - похожие друг на друга имена вроде `IlIl` и `O0O0`;
  - имена не латиницей;
  - `\u`-последовательности в коде;
  - строки длиной в тысячи символов или средняя строка длиннее 220 символов;
  - строки, расшифровываемые через XOR;
  - длинные закодированные строки (base64) и большие зашитые массивы данных;
- **он прячет код**: `DexClassLoader`, `InMemoryDexClassLoader`, `PathClassLoader`, `DexFile`, `defineClass`, `System.load`/`loadLibrary`, `Runtime.exec`, `ProcessBuilder`;
- **пакет не совпадает с исходниками**:
  - в `classes.dex` есть класс, которого нет в отправленных `.java`;
  - в пакете есть файлы, кроме `manifest.json`, `classes*.dex`, `icon.png`;
  - `manifest.json` пакета отличается от отправленного.

Редактор проверяет обфускацию ещё на телефоне и показывает причины до отправки.

### Gemini

После автоматических проверок код читает Gemini и пишет, что делает плагин и нет ли в нём опасного: кражи данных или токенов, скрытой отправки данных, вредных действий от имени пользователя. Если Gemini считает код запутанным, заявка отклоняется автоматически. Остальное — подсказка модератору.

### Модерация

Модератор видит исходники, разрешения, вердикт Gemini и одобряет или отклоняет. Одобренный плагин появляется в магазине с отметкой «Проверен» и ником отправителя. Обновление — новая отправка с тем же `id` и новой `version`.

### Хорошая заявка

- понятные имена классов, методов и переменных;
- в `permissions` только то, что действительно используется;
- описание, из которого ясно, что делает плагин;
- никаких скрытых сетевых запросов: адреса — строками в коде, а зачем — в описании.

### Магазин в браузере, отзывы и установка по ссылке

Магазин открыт и в браузере: `https://ttcuz.ttcuz1337.workers.dev/store.html`. У каждого плагина своя страница — `store.html#plugin-<id>`, ей удобно делиться.

- **«Установить в ttcuz»** открывает ссылку `ttcuz://plugin/<id>`: запускается TikTok с модом, магазин прокручивается к плагину и предлагает его установить (с разрешениями). Такую ссылку можно ставить и в свой README, Telegram и т.п.
- **Отзывы**: 1–5 звёзд и текст до 600 символов, по одному отзыву от аккаунта на плагин (повторная отправка меняет отзыв). Оставить отзыв можно только из приложения — он привязан к облачному профилю мода, накрутить нельзя. В браузере отзывы видны всем, кнопка «Оценить» открывает приложение (`ttcuz://plugin/<id>?review=1`). Средняя оценка видна в магазине и в каталоге (`rating`).
- **Обновления**: отправьте из редактора тот же ID с версией выше — заявка уйдёт как обновление (поле «Что нового» увидят модератор и пользователи). Обновлять плагин может только аккаунт, который прислал его первым.

## 18.1. Эффекты: размытие, motion blur, шейдеры (API 3)

Разрешение `effects`. Всё рисуется через `RenderEffect` на потоке отрисовки — быстро и без копий кадра. Работает на Android 12+ (`effectsSupported()`), шейдеры — на Android 13+ (`shadersSupported()`); на старых телефонах вызовы просто ничего не делают и возвращают `false`/`null`. Когда плагин выключают, все его эффекты снимаются сами.

| Метод | Что делает |
|---|---|
| `boolean blur(View v, float radius)` | Размытие по Гауссу, радиус в px (до 150); `0` убирает |
| `boolean blur(View v, float rx, float ry)` | Размытие сильнее по одной оси: `blur(v, 30, 0)` — смаз вбок |
| `Runnable motionBlur(View v, float strength)` | **Motion blur**: view размывается по направлению своего движения на экране, настолько, насколько сдвинулся с прошлого кадра. `strength` 1 — естественно, до 4. Пока view стоит — ничего не стоит по батарее. Возвращает то, что его выключает |
| `boolean colourMatrix(View v, float[20] m)` | Цветовая матрица 4×5 (как `android.graphics.ColorMatrix`): ч/б, сепия, контраст, инверсия |
| `Object shader(View v, String agsl)` | Свой шейдер AGSL поверх view; view внутри — `uniform shader content;`. Возвращает `RuntimeShader` |
| `boolean uniform(View v, String name, float... values)` | Меняет `uniform float` шейдера и перерисовывает |
| `void clearEffect(View v)` | Снимает эффект |
| `Runnable everyFrame(Frame f)` | Колбэк на каждый кадр (без разрешения) — для своих анимаций; остановите, когда не нужен |

```java
// @uses effects: ч/б фильтр на весь экран
ttcuz().colourMatrix(content, new float[]{
    .33f,.33f,.33f,0,0,  .33f,.33f,.33f,0,0,  .33f,.33f,.33f,0,0,  0,0,0,1,0});

// @uses effects: волна по экрану
String agsl = "uniform shader content; uniform float t;"
    + "half4 main(float2 p){ return content.eval(p + float2(sin(p.y/40+t)*6, 0)); }";
ttcuz().shader(content, agsl);
ttcuz().everyFrame(nanos -> ttcuz().uniform(content, "t", nanos / 1e9f));
```

Motion blur для ленты — готовый пример [`examples/motion-blur`](../examples/motion-blur): он вешает `motionBlur` на каждое видео в списках экрана.

**Не перестарайтесь:** эффект на весь экран + `everyFrame` перерисовывают экран каждый кадр и едят батарею. `motionBlur` этим не страдает.

## 18.2. Интерфейс и настройки мода (API 3)

Разрешение `mod` (показывается пользователю как чувствительное). Даёт три вещи.

**1. Свои строки прямо в настройках мода** — в разделе «Плагины», отдельной карточкой с названием плагина:

```java
// @uses mod: свой ползунок в настройках мода
@Override public void onModSettings(PluginSettings page) {
    page.toggle("on", "Включено", true).slider("strength", "Сила", 1, 4, 2);
}
```

Строки те же, что в `onSettings` (раздел 10), значения хранятся в `prefs()` плагина, изменения приходят в `onPreferenceChanged`.

**2. Вид экранов мода.** `onModScreen(Activity, ViewGroup root)` вызывается каждый раз, когда экран настроек мода нарисован заново, — можно перекрасить, переставить, спрятать или добавить что угодно. `onModPanel(String title, ViewGroup content)` — когда открывается любое окно мода (лист снизу); `title` — его заголовок.

```java
// @uses mod: скругляет все карточки настроек сильнее
@Override public void onModScreen(Activity a, ViewGroup root) {
    for (View v : ttcuz().views(root, View.class))
        if (v.getBackground() instanceof android.graphics.drawable.GradientDrawable)
            ((android.graphics.drawable.GradientDrawable) v.getBackground().mutate()).setCornerRadius(ttcuz().dp(28));
}
```

Изменения во view живут до следующей перерисовки экрана — поэтому делайте их в `onModScreen`, он вызывается после каждой. `views()` требует ещё `interface`.

**3. Настройки самого мода.** `modSettings()` — все открытые настройки мода с значениями (удобно посмотреть ключи), `modSetting(key)` — одна, `setModSetting(key, value)` — поменять (`Boolean`, `Integer`, `Long`, `Float`, `String`; `null` возвращает значение по умолчанию), `refreshModScreen()` — перерисовать экран настроек, если он открыт. Другие плагины узнают об изменении через событие `mod.setting`. Закрыты всегда: аккаунты, токены, ключи, PIN, всё админское, облако, резервные копии и настройки плагинов — такая попытка бросает `SecurityException`. Часть настроек применяется сразу, часть — после повторного открытия экрана или перезапуска TikTok.

## 18.3. API 4: события TikTok, плеер, автоматизация, селекторы

### События TikTok (`watch`)

```java
// @uses watch: считает просмотренные видео
@Override public void onTikTok(String event, java.util.Map<String, Object> data) {
    if ("video:selected".equals(event)) ttcuz().log("видео " + data.get("id") + " от @" + data.get("author"));
}
```

| Событие | Когда | `data` |
|---|---|---|
| `video:selected` | Лента остановилась на видео | `id`, `author` (ник), `authorId`, `description`, `post` (объект `Aweme`) |
| `comments:open` / `comments:close` | Комментарии видео открыты / закрыты | `video` — id видео |
| `dm:message` | В чате показано сообщение (приходит и при прокрутке) | `id`, `time` (мс), `incoming` |
| `dm:deleted` | Собеседник удалил сообщение | `id` |
| `search:query` | Пользователь что-то искал | `query`, `source` |
| `feed:page` | Пришла страница ленты (после `onFeed`) | `count` |
| `app:foreground` / `app:background` | TikTok вышел на экран / ушёл с него | `screen` / — |

`data` только для чтения. Хук вызывается на главном потоке — тяжёлую работу переносите в `away()`. События собираются, только если хоть один включённый плагин переопределил `onTikTok`, поэтому без таких плагинов они ничего не стоят.

### Селекторы (`interface`)

| Селектор | Что находит |
|---|---|
| `#name` | id ресурса: `#title` или `#com.zhiliaoapp.musically:id/title` |
| `@текст` | текст, содержащий «текст» (без учёта регистра) |
| `@=Текст` | ровно такой текст |
| `~описание` | contentDescription, содержащий «описание» |
| `.Класс` | класс: простое имя (`.TextView`) или полное |
| `a|b` | любой из вариантов |

```java
// @uses interface: прячет кнопку «LIVE» на всех экранах
ttcuz().hide("~LIVE|@=LIVE");
ttcuz().log(ttcuz().tree(content));   // дерево экрана в журнал — чтобы найти нужный селектор
```

Большинство id TikTok запутаны и меняются от версии к версии, поэтому надёжнее искать по тексту (`@`), описанию (`~`) и классу (`.`). `hide` держит элементы скрытыми, пока плагин работает: правила повторяются после каждой перерисовки экрана, а при остановке плагина всё возвращается.

### Нажатия за пользователя (`automation`)

`click(view)` и `longClick(view)` — как нажатие пальцем по этому элементу; `tap(activity, x, y)` и `swipe(...)` — касания по координатам экрана; `type(field, text)` — текст в поле ввода. Разрешение показывается пользователю красным: плагин действует от его имени.

### Плеер (`player`)

```java
// @uses player: пауза на время своего окна
if (ttcuz().playing()) ttcuz().pause();
ttcuz().speed(1.5f);
Object post = ttcuz().video();      // объект Aweme; читать его — через рефлексию (tiktok)
```

### Плагины вместе и повторяющаяся работа

```java
ttcuz().expose("count", argument -> counter);                         // в одном плагине
Object n = ttcuz().call("com.me.counter", "count", null);            // в другом (events)
Runnable stop = ttcuz().every(() -> ttcuz().log("тик"), 60_000);      // раз в минуту, пока TikTok на экране
```

Полный пример — [`examples/api4-tour`](../examples/api4-tour).

## 18.4. Уровни доступа (API 4)

В карточке плагина под ключом сверху написано, насколько далеко он достаёт:

| Уровень | Разрешения | Как показывается |
|---|---|---|
| Безопасный | `interface`, `effects`, `text`, `feed`, `colours`, `region`, `events`, `notifications`, `storage`, `VIBRATE` | обычным цветом |
| Расширенный доступ | `network`, `clipboard`, `account`, `mod`, `player` | с пояснением |
| Полный доступ | `tiktok`, `watch`, `automation`, разрешения Android (камера, микрофон, местоположение…) | красным предупреждением: «Видит и делает в TikTok то же, что и вы» |

## 18.5. Чего нет в API 4 и почему

Концепт «полной свободы» шире, чем можно честно сделать внутри мода. Чего нет:

- **Перехват любого метода (`hook.method`)** — на ART для этого нужен нативный фреймворк (LSPlant, Pine и т.п.), в моде его нет. Вместо этого — события `onTikTok`, хуки из раздела 8 и рефлексия.
- **Перехват и подмена сетевых запросов TikTok** — TikTok ходит в сеть через свою нативную библиотеку; плагину доступны свои запросы (`http`).
- **Свои Activity, Service, виджеты на рабочем столе** — Android читает их из манифеста при установке приложения; плагин появляется позже.
- **Другие языки (Python, WASM, Lua) и горячая перезагрузка без переустановки** — плагин это Java-код в dex; обновление ставится поверх за секунды, настройки сохраняются.
- **Готовые боты: автоподписки, автокомментарии, автолайки, отправка подарков в эфирах** — мод не даёт таких функций нарочно: это спам и траты денег от имени человека, за них блокируют аккаунты. `automation` нажимает только туда, куда плагин явно указал, и пользователь видит это разрешение красным.

## 19. Версии API и совместимость

| API | Что появилось |
|---|---|
| 1 | Хуки экранов, текста, ников, ленты, цвета, региона, событий, настроек; `prefs`, `accountPrefs`, `data`, `bundle`, рефлексия, `log`, `toast`, `ui`, `later`, `away`, `emit` |
| 2 | Разрешения в манифесте; `onScreen`, `onPermission`; `overlay`, `find`, `views`, `dialog`, `menu`, `palette`, `dp`, анимации; разрешения Android; `http`, `notify`, `copy`/`paste`, `saveDownload`, `open`, `share`, `vibrate` |
| 3 | `effects`: `blur`, `motionBlur`, `colourMatrix`, `shader`/`uniform`, `clearEffect`, `everyFrame`; `mod`: `onModScreen`, `onModPanel`, `onModSettings`, `modSettings`/`modSetting`/`setModSetting`, `refreshModScreen` |
| 4 | `watch`: `onTikTok` (видео, комментарии, сообщения, поиск, лента, приложение); `player`: `video`, `pause`, `play`, `speed`, `saveVideo`; `automation`: `click`, `tap`, `swipe`, `type`; селекторы `query`/`tree`/`hide`/`inject`; `expose`/`call`, `every`; уровни доступа |

Мод ставит плагины любого API от 1 до своего. Плагин API 4 на моде, который знает только API 3, не установится — с понятной причиной. Отметив `effects` или `mod` в редакторе, вы переводите плагин на API 3, а `watch`, `player` или `automation` — на API 4.

**Как перейти на API 4**: поставьте `"api": 4` и перечислите в `permissions` всё, что использует плагин. Если что-то забыли, плагин не запустится и в карточке будет написано, какого разрешения не хватает.

**Плагины другого формата.** ttcuz ставит и запускает плагины совместимого формата (`.mtp`, `.mtb` — такой же ZIP с `manifest.json`, `classes.dex`, `icon.png`). Переименовывать не нужно: «Установить .ctt» принимает файл с любым расширением. Их хуки, настройки, окна, загрузки и журнал работают через ttcuz, названия и описания на языке телефона (`name_ru`…) поддерживаются. Такие плагины считаются плагинами API 1.

## 21. Ошибки и их решение

### При сборке

| Сообщение | Причина и решение |
|---|---|
| `javac not found: install JDK 17 or newer` | Не установлен JDK или он не в PATH. Termux: `pkg install openjdk-17` |
| `no manifest.json in …` | Неверная папка: укажите ту, где лежит `manifest.json` |
| `manifest.json has no id, entry …` | Не хватает обязательных полей |
| `api must be 1..4` / `tiktok '…'` | Плагин под другую версию API или TikTok |
| `permissions must be a list of names…` | `permissions` — не список или имя с недопустимыми символами |
| `manifest.json is not valid JSON` | Лишняя или пропущенная запятая, кавычки «ёлочки» вместо `"` |
| `id 'a b': Latin letters, digits…` | Недопустимые символы в `id` |
| `entry 'Main' is not a fully qualified class name` | Нужно полное имя: `com.me.hello.Main` |
| `the entry class … is not among the compiled classes` | Пакет в `.java` не совпадает с `entry` или путём папки |
| `no .java under …/java` | Исходники должны лежать в `java/` |
| `icon.png is not a PNG` | Файл переименован из jpg/webp: сохраните настоящим PNG |
| `javac failed` / окно «Сборка не удалась» | Ошибка в коде: строка и причина показаны в тексте |
| `OutOfMemoryError` (Termux) | Закройте другие приложения: D8 нужно несколько сотен МБ |

### При установке и запуске

| Сообщение | Причина и решение |
|---|---|
| «Плагину нужны разрешения в manifest.json: …» | Хук переопределён без разрешения — добавьте названное в `permissions` |
| `SecurityException: plugin … needs "…"` | Вызов `ttcuz()` без разрешения — добавьте его в `permissions` |
| `the code uses …, which manifest.json "permissions" does not ask for` | Сборка нашла в коде вызов без разрешения (раздел 6.1) — добавьте его в `permissions` |
| `SecurityException: … the mod setting "…" is not open to plugins` | Эта настройка мода закрыта для плагинов (аккаунты, токены, админское) |
| `uses must be an object…` | `uses` в манифесте — не объект «разрешение → строка» |
| «Не хватает разрешений» в редакторе | Красные строки под кодом — нажмите на них, чтобы отметить разрешения |
| `http() on the main thread: use away()` | Сеть только из `away()` |
| `only https:// addresses` | `http` не ходит по `http://` |
| «Нужен ttcuz Plugin API N» | Плагин требует API новее, чем у мода: обновите ttcuz |
| «Главный класс не является плагином» | Класс из `entry` не наследует `TtcuzPlugin` |
| «Класс плагина абстрактный» | `entry` указывает на абстрактный класс |
| «Безопасный режим: плагины не запускаются при старте» | Включён безопасный режим: выключите его в настройках плагинов |

### При отправке на проверку

| Сообщение | Что делать |
|---|---|
| «Код не прошёл проверку» + список причин | Уберите запутывание: понятные имена, без `\u` в коде, без шифрованных строк и зашитых данных |
| «Пакет не совпадает с исходниками» | Отправляйте из редактора: он собирает пакет из тех же исходников |
| `rate_limited` | Не больше 6 отправок в час с одного адреса |
| «Пакет больше 1 МБ» | Уменьшите картинку и код (файлом плагин можно поставить и до 20 МБ) |

## 22. Частые вопросы

**Плагин работает после перезапуска TikTok?** Да: включённые плагины запускаются при каждом старте (кроме безопасного режима).

**Где хранить данные?** Мелкие — в `prefs()`/`accountPrefs()`, файлы — в `data()`. При обновлении плагина всё сохраняется, при удалении — удаляется.

**Можно ли использовать Kotlin?** Сборщик компилирует Java. Kotlin-код можно собрать в Java-совместимый dex отдельно, но магазин принимает только исходники на Java.

**Можно ли несколько файлов?** Да, до 32 `.java` в разных пакетах внутри `java/`.

**Как сделать плагин для одного аккаунта?** Храните настройки в `accountPrefs()` и проверяйте `accountId()` (разрешение `account`).

**Почему кнопка с шестерёнкой не появляется?** Нужно переопределить `onSettings` или `onOpenSettings`.

**Почему изменения в TikTok «откатываются»?** TikTok перерисовывает экран своими данными. Повторяйте изменение в `onScreen` или `onView`.

**Где полные сигнатуры?** `sdk/cat/ttcuz/framework/plugin/`: `TtcuzPlugin.java`, `PluginContext.java`, `PluginSettings.java`.
