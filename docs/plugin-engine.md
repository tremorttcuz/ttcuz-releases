# ttcuz Plugin Engine — API 1

## Создание

С каждой APK-сборкой создаётся `*-plugin-sdk.jar`. Требуются JDK, Python,
`android.jar` и `r8.jar` — те же инструменты, что используются для APK.

```text
python -m ttcuz.plugin examples/hello --sdk path/to/ttcuz-plugin-sdk.jar --android path/to/android.jar --r8 path/to/r8.jar -o hello.ctt
```

Java-файлы находятся в `java/`, ресурсы — в `assets/`, библиотеки — в
`lib/arm64-v8a/` и других ABI. Дополнительные зависимости компиляции задаются
повторяемым `--classpath`; для включения JAR в итоговый DEX используется `--include`.
Поддерживаются `--release 8`, `11` и `17`, по умолчанию 8. Корень ZIP:

```text
manifest.json
classes.dex
classes2.dex       (необязательно, без пропусков нумерации)
assets/...
lib/arm64-v8a/...
resources.apk     (необязательно; автор сам загружает Android Resources)
```

```json
{
  "id": "ttcuz.hello",
  "name": "Привет",
  "version": "1.0.0",
  "author": "Tremor",
  "description": "Описание в одну строку",
  "api": 1,
  "entry": "ttcuz.examples.Hello"
}
```

`entry` — публичный класс с публичным конструктором без аргументов,
наследующий `cat.ttcuz.framework.plugin.TtcuzPlugin`.
Необязательное поле `tiktok` задаёт точную совместимую версию TikTok;
без него дополнительного ограничения по версии нет.

## API

`ttcuz()` возвращает `PluginContext`:

| Метод | Назначение |
|---|---|
| `app()`, `screen()`, `hostLoader()` | Контекст, текущая Activity, загрузчик классов приложения |
| `type()`, `method()`, `field()` | Доступ к настоящим классам, методам и полям, включая непубличные, если Android разрешает |
| `prefs()`, `accountPrefs()` | Настройки плагина и текущего аккаунта |
| `bundle()`, `data()` | Каталог кода/ресурсов и отдельный каталог данных |
| `accountId()`, `accent()` | Текущий UID и цвет акцента |
| `ui()`, `later()`, `away()` | Главный поток, отложенная работа и фоновый исполнитель |
| `log()`, `toast()`, `emit()` | Журнал, сообщение, событие другим плагинам |

API не запрещает обычные Android/Java API, reflection, сеть, собственные потоки
или нативные библиотеки. SDK не выдаёт root, новые разрешения Android и не
снимает ограничения операционной системы. Автоматической подмены произвольного
ART-метода нет: для неё автору нужна своя совместимая реализация перехвата.
Существующие точки перехвата перечислены ниже.

## События

| Метод плагина | Когда вызывается |
|---|---|
| `onLoad()` | В потоке загрузчика; подготовка файлов и данных |
| `onStart()`, `onStop()` | В главном потоке, при запуске и остановке экземпляра |
| `onActivityCreated/Resumed/Paused/Destroyed(Activity)` | Жизненный цикл экранов |
| `onAccountChanged(uid)` | Текущий аккаунт изменился; при старте также передаётся текущий UID |
| `onPreferenceChanged(scope,key)` | Настройки host, plugin или plugin-account изменились |
| `onSettings(PluginSettings)` | Построение стандартных настроек плагина |
| `onOpenSettings(Activity)` | Собственное окно; вернуть `true`, чтобы не открывать стандартное |
| `onView(View)` | Оформление созданного/изменившегося View, без обхода каждого кадра |
| `onColour(int)` | Цвет после основной обработки акцента; вернуть новый цвет |
| `onText(TextView,CharSequence)` | Текст перед обработкой имён и значков |
| `onNickname(uid,name)` | Имя после локального переименования |
| `onRegion(key,value)` | Данные SIM/сети после выбора региона |
| `onFeed(List)` | Страница ленты перед встроенными фильтрами |
| `onEvent(name,payload)` | Произвольные события; вложенные разные события поддерживаются |

Преобразования вызываются в потоке исходного вызова. В них нельзя выполнять
сетевые запросы и тяжёлую работу. Порядок плагинов стабилен: по ID при запуске,
переустановка сохраняет позицию. Возврат `null` из преобразования сохраняет
предыдущее значение. Повторный вход в преобразования из самого плагина
возвращает исходное значение и не запускает рекурсию. Обработчики цвета,
текста, View и ленты включаются только если плагин действительно их переопределил.

Для `onView` используйте свои теги/ID: повторный вызов не должен дублировать
кнопки. При поздней загрузке плагин получает текущий `onAccountChanged` и
`onActivityResumed`; прошедшие события создания экранов не воспроизводятся.

## Настройки и завершение

```java
@Override public void onSettings(PluginSettings settings) {
    settings.toggle("enabled", "Мой эффект", true)
        .slider("strength", "Сила", 0, 100, 50)
        .choice("mode", "Режим", new String[]{"Обычный", "Компактный"}, 0)
        .action("Проверить", () -> ttcuz().toast("Работает"));
}
```

Доступны также `text()` и `view()` для собственных Android View. Стандартные
строки используют оформление меню и сохраняют значения в `ttcuz().prefs()`.
Для аккаунтных настроек используйте `accountPrefs()` в собственном интерфейсе.

При остановке движок отменяет задачи, созданные через `ui/later/away`, и
отписывает свои слушатели. Собственные потоки, сокеты, добавленные View,
слушатели и нативные перехваты автор освобождает в `onStop()`. Уже запущенную
пользовательскую Java-задачу нельзя гарантированно завершить без её участия.
Удаление пакета сохраняет настройки и `data()`, чтобы переустановка их вернула.

Java-исключение в обработчике записывается в журнал и останавливает этот
экземпляр до ручной перезагрузки. Это не изоляция: native crash, бесконечный
цикл или повреждение данных произвольным кодом невозможно нейтрализовать
обычным `try/catch` в том же процессе.

Старые Python-плагины и бинарники для другого SDK не совместимы автоматически.
Исходники переносятся на этот API и собираются заново. Оба поставляемых
примера уже написаны для ttcuz. Локальный импорт работает без сервера.

## Магазин и модерация

Нативный магазин и редактор находятся в разделе «Плагины» внутри мода.
Встроенный редактор сохраняет черновики, экспортирует исходный ZIP и отправляет Java-код в очередь. Веб-редактор остаётся дополнительным интерфейсом.
Пакет `.ctt` собирается командой выше. Заявки и анализ ИИ приходят
в Discord DM через существующие `DISCORD_BOT_TOKEN`/`DISCORD_USER_ID`.
В меню владельца есть «Модерация магазина»: создаётся сеанс на 10 минут,
постоянный ключ профиля не передаётся в браузер. `plugin-admin.html` также
принимает подтверждённый ключ профиля владельца вручную.
Владелец принимает/отклоняет исходники, назначает/удаляет марки авторов,
публикует или удаляет пакеты. Для отметки проверки он подтверждает, что
сам собрал пакет из принятых исходников; это ручная аттестация, не
автоматическое доказательство воспроизводимой сборки.

Публикация отклоняет выявленные признаки обфускации и скрытой загрузки кода.
Статическая проверка не обнаруживает любую возможную обфускацию.
ИИ описывает риски и не принимает решение за владельца. Его отказ/таймаут
не означает безопасность и не удаляет заявку. Лимит пакета в D1 — 1 МБ,
исходников — 240 КБ. Настройки локального движка этим не ограничиваются.

Сервер: миграция `0011-native-plugin-review.sql`, секрет `GEMINI_API_KEY`,
модель `GEMINI_MODEL` (по умолчанию `gemini-3.5-flash-lite`). Ключ только
в Worker secrets, не в APK, страницах или архиве. API Google:
https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite
