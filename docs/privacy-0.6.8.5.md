# 0.6.8.5 — исходники, без сборки APK

База: исходники 0.6.8.4 и официальный TikTok 47.2.41.

## Приватность из TT Extras 1.0.1

Встроены только функции приватности предоставленного плагина:

- Не отправлять свой онлайн. Получение чужих статусов не отключается; в родных настройках TikTok статус активности остаётся включённым.
- Не отправлять просмотр историй.
- Не отправлять прочтение переписок, включая групповые чаты, запросы и пакетные отметки.
- Не отправлять «печатает».
- Не отправлять посещение профилей.

Используются существующие три настройки и две новые строки в разделе «Приватность».
Настройки независимы и по умолчанию выключены. Отдельный файл плагина, его меню,
загрузки историй, лимиты, регион, браузер и надпись о последней активности не включены.

`PrivacyAdapters`, `PrivacyImGate`, `PrivacyReflect` адаптированы из
GhostMode/ImEventGate/Reflect переданного архива. Обёртки устанавливаются на реальные
отправители текущей сессии, API историй и посещений профилей. IM обрабатывается и на
HTTP, и на WebSocket: команды берутся из родного enum `X.0S5V`. Обычные сообщения,
вложения и запросы данных делегируются оригиналу. Для HTTP блокировка завершает callback
локальной отменой; для историй используется отменённый Single, для профилей пустой Observable.

Ранее заблокированная последовательность IM не выпускается при автоматической повторной
отправке после выключения настройки. Ключ учитывает аккаунт, команду и номер пакета.
При смене аккаунта обёртки пересоздаются; чужие изменения кешированных сервисов при
восстановлении не перезаписываются. Проверка подключения работает раз в секунду только
при открытой Activity и включённых опциях. После ухода с экрана таймер снимается.

Прежние точечные защиты отправителей сохранены, в том числе на раннем запуске.
Защита истории теперь возвращает локальную отмену вместо вымышленного успешного ответа.
Уже отправленные события ни один из этих переключателей не удаляет.

## Синхронизация градиентов ников

1. Ручные изменения оформления больше не ждут завершения приватного резервного
   копирования. Для свежей установки без изменений ожидание восстановления сохранено,
   чтобы не опубликовать настройки по умолчанию поверх сохранённых.
2. Загрузка публичного профиля различает подтверждённый HTTP 404 и сетевой сбой.
   Ошибки 429/5xx, таймаут и некорректный ответ не превращаются в «у пользователя нет
   оформления»: прежний подтверждённый градиент сохраняется. HTTP 404 по-прежнему удаляет
   запись, например после выключения публикации владельцем.
3. Неудачная отправка автоматически повторяется с существующей паузой от 30 секунд
   до 10 минут. Новое изменение, смена аккаунта и выключение публикации отменяют старую
   попытку. Ситуация, требующая подтверждения владельца, не запускает бесконечную отправку.
4. Публикация читает JSON ошибки сервера: `nickname_font_missing` сбрасывает кеш загрузки
   шрифта и позволяет загрузить его заново при следующей попытке. Пустой сетевой ответ
   больше не разбирается как JSON.

Публикация оформления по-прежнему управляется владельцем и требует доступного сервера.
Синхронизация поддерживается клиентами ttcuz с соответствующей реализацией.

## Проверка

- На оригинальном APK проверено наличие всех 55 нужных нативных методов и полей.
  Это структурная проверка DEX, без его изменения и без сборки.
- Выполнены 13 проверок приватности из плагина и добавлена проверка изоляции номеров
  пакетов разных аккаунтов: блокировка read/typing, обычные сообщения, общая защита
  повторов HTTP/WS, включение/выключение, делегирование ошибок и восстановление кешей.
- Проверены независимость настроек, жизненный цикл таймера и смена аккаунта;
  синхронизация при сбое backup, HTTP 404 против 429/5xx/таймаута, лимит JSON,
  автоматическая повторная отправка и её отмена.
- Проверены совместимость чтения старых профилей, DEX-кеш и предыдущие изменения
  личных сообщений и шрифтов. Весь Java-код проверен javac с Android API 35.
- Телефон/эмулятор не подключён: работа сетевых операций и показа настроек на устройстве
  пока не подтверждена. D8, сборка APK и публикация релиза не запускались.
- При проверке `/health` облако сначала ответило HTTP 403, а с User-Agent приложения
  `ttcuz` — HTTP 429 и страницей Cloudflare «temporarily rate limited».
  Пакет исходников не изменяет правила доступа Cloudflare, поэтому сквозную синхронизацию через рабочее облако
  подтвердить пока нельзя. Сервер в этой задаче не развёртывался.
