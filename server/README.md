# Сервер ttcuz

Основной сервер — Cloudflare Worker в `cloudflare/`. Точка входа `worker.mjs`,
настройки развёртывания `wrangler.toml`, база D1 `ttcuz-profiles` (binding PROFILES).
Статические страницы обслуживаются binding ASSETS.

## Подсистемы

| Файл | Назначение |
| --- | --- |
| `profiles.mjs` | Профили, значки и административные операции |
| `appearance.mjs` | Резервные копии оформления |
| `device.mjs` | Восстановление ранее доверенного устройства |
| `plugins.mjs` | Каталог, пакеты .ctt, сеансы владельца |
| `native-plugins.mjs` | Заявки Java, модерация и марки авторов |
| `plugin-analysis.mjs` | Проверка исходников и запрос к Gemini |
| `discord.mjs` | Уведомления, включая личные сообщения владельцу |
| `crashes.mjs` | Приём отчётов об ошибках |
| `releases.mjs` | Проверка обновлений |

## Установка и обновление

1. Настройте аккаунт Cloudflare и D1 в `cloudflare/wrangler.toml`.
2. Для новой базы используйте схему, для существующей — недостающие миграции
   из `cloudflare/migrations/`. Проверяйте уже применённые миграции;
   обновление кода не должно пересоздавать базу или сбрасывать подтверждения.
3. Для очереди Java-плагинов нужна миграция `0011-native-plugin-review.sql`.
4. Секреты задавайте через Wrangler, не добавляйте их в файлы проекта:
   `DISCORD_BOT_TOKEN`, `DISCORD_USER_ID` (получатель DM), `GEMINI_API_KEY`.
   Необязательная переменная `GEMINI_MODEL` выбирает модель разбора.
   Перечень других секретов для конкретной подсистемы см. в её документации.
5. Проверьте упаковку и разверните Worker:

```sh
cd server/cloudflare
npx wrangler deploy --dry-run
npx wrangler deploy
```

Не публикуйте `.dev.vars`, `.env`, `.wrangler/` и ключи. Их нет в чистом снимке
исходников. Новые окна Android требуют отдельного APK, развёртывание Worker
обновляет только сервер и веб-страницы.

## Плагины и владелец

[Полное руководство](../docs/plugins.md) описывает .ctt, API и публикацию.
Каталог — `GET /plugins/catalog.json`; заявка — `POST /plugins/native/submit`.
На отправку действуют ограничения размера, читаемости исходников и частоты.
Заявка сохраняется до обращения к Discord и ИИ. Ошибка анализа не означает
одобрения и не удаляет заявку. Административные операции требуют подтверждённого
владельца или действующего краткосрочного сеанса.

Сервер автоматически восстанавливает токен ранее доверенного устройства,
сохраняя запись verified. Это не восстановление по одному произвольному UID.
Существующие подтверждения не стираются при развёртывании.
