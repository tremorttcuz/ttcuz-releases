# Совместимость скачивания и обновлений

Основа: ZIP 0.6.5.10-optimized. Сохранены оптимизации и исключение лички и строки поиска из антивыгорания. APK не собирался.

Исправления
- Net.download: до трёх попыток при временных HTTP 408/429/5xx, сетевых тайм-аутах, ошибках соединения и неполной передаче. Короткая задержка прерывается отменой. Неподходящие ответы HTTP, пустые файлы и самопроизвольный HTTP 206 не считаются успехом. Перенаправление с HTTPS на HTTP по-прежнему запрещено; проверка TLS не отключалась.
- Длина файлов читается как 64-битное число. Проверяется лимит и свободное место. Ответ без Content-Length поддерживается. Потоки закрываются при ошибке открытия файла; у каждой попытки собственный временный файл, очищаемый после завершения.
- Сохранение медиа унифицировано: видео -> Movies/ttcuz, фото -> Pictures/ttcuz, аудио -> Music/ttcuz. На Android 10+ используется MediaStore; IS_PENDING снимается только после окончания записи. Неудачная запись очищается, а ошибка очистки не заменяет исходную ошибку.
- На Android 6–9 перед скачиванием видео/фото/аудио, аватара, стикера и снимка кадра запрашивается WRITE_EXTERNAL_STORAGE, если разрешения ещё нет. После разрешения отложенные операции продолжаются; отказ не запускает загрузку. На Android 10+ этот запрос не открывается.
- Для старых Android медиа сначала записывается во временный файл. Ошибка/отмена не уничтожает уже существующий файл. Ошибка фонового сканирования галереи не превращает успешно записанный файл в ошибку скачивания.
- APK обновления сначала сохраняется отдельно, затем проверяется: ZIP с манифестом и DEX, имя пакета, минимальная версия Android (API 24+), код версии, подпись с учётом истории смены сертификата (API 28+), наличие подходящей архитектуры процессора. Неподходящий APK не заменяет ранее сохранённое обновление и не передаётся установщику.
- Ожидание разрешения на установку сохраняется в настройках и переживает перезапуск процесса. APK передаётся с MIME, ClipData и правом чтения; предусмотрен альтернативный системный intent установки. Провайдер отдаёт установщику имя и размер файла, учитывая запрошенные колонки.
- Патчер объявляет отдельную неэкспортируемую Activity для системного запроса разрешения и разрешение записи; ограничение доступа установщика не ослаблялось.

Проверки
- Все Java-исходники компилируются с Android SDK.
- Объявление Activity и разрешения проверено на манифесте исходного TikTok с повторной сериализацией бинарного XML.
- Широкий запуск: 75 runtime-проверок, 73 прошли. Две существующие ошибки: test_script_runtime и test_social_library_runtime (старые тестовые заглушки); подтверждены на предыдущей версии. Старый тест скачивания исправлен добавлением недостающей заглушки и расширен.
- Дополнительно повторены проверки обновления, разрешений, метаданных провайдера и записи медиа после последних изменений: все прошли.
- Проверены временная ошибка сервера и предел повторов, отмена, сохранность прежнего файла, очистка временных файлов, пустой/неполный ответ, неизвестная длина, размер >2 ГБ в заголовке и ограничение объёма, запрещённый переход на HTTP.
- Проверены неправильный пакет, несовместимая версия Android, старая версия, чужая подпись, допустимая история сертификатов, неподходящая архитектура, HTML вместо APK, группировка запросов разрешения, отказ и разрешение записи, Android API 23/28/29/35 в тестовых окружениях.

Ограничения
Это проверки кода и Android-заглушек, а не испытание на каждом телефоне. Не гарантируются работа сети/сервера, наличие места, разрешения пользователя, совместимость будущего APK с конкретной прошивкой и отсутствие ограничений производителя. Повторы запускают передачу заново; возобновление с байтового смещения и восстановление незавершённых загрузок после убийства процесса не добавлены. Для скачивания и установки рекомендуется держать приложение открытым. Поведение установщика, MediaStore и диалогов разрешений на реальном устройстве остаётся непроверенным. Подпись текущего APK и серверного обновления должна быть совместима; этот системный запрет не обходится.
