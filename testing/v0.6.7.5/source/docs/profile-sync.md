# Синхронизация оформления профилей ttcuz

Сервер: https://ttcuz.daniilsolovatulin.workers.dev
Хранилище: Cloudflare D1 `ttcuz-profiles`, привязка `PROFILES`.

## Для пользователя

В разделе «Профиль» нажмите «Подтвердить профиль», скопируйте временный код и добавьте его отдельной строкой в описание своего TikTok. Когда TikTok загрузит UID и @ник, ttcuz проверяет публичное описание автоматически. Если профиль уже открыт в TikTok, ник подставляется сам; при временной ошибке повторная попытка запускается раз в 10 минут. Проверка сравнивает UID, ник и код в описании публичного профиля. После подтверждения код можно удалить. Пароль, cookies и токены TikTok не передаются.

Показ другим включён по умолчанию; обновление также исправляет значение, которое прежняя версия могла ошибочно сохранить выключенным. После подтверждения ttcuz автоматически публикует значок, цвета ника, жирность, свечение, анимацию, её скорость, размер и положение значка. Другие пользователи должны иметь версию мода с этим механизмом. Изменения отправляются после короткой паузы; чтение кешируется на пять минут. Выключение отправляет запрос на скрытие публичного оформления. При ошибке сети отключение на сервере не гарантируется — проверьте статус отправки.

Профиль, уже открытый во время загрузки оформления, обновляется после ответа сервера. При перепроверке просроченного кеша последнее подтверждённое оформление остаётся на экране, пока сервер не вернёт новое.

Для смещения короны автора предусмотрены отдельные координаты: они сохраняются локально и передаются в публичном оформлении. В предпросмотре корону и значок можно переместить пальцем; выбранный значок располагается непосредственно у ника, перед короной. Та же последовательность используется в профиле TikTok.

Создатель ttcuz может выдать или снять значок сообщества из карточки оформления профиля. Достаточно указать публичный `@ник`; Worker проверяет его профиль TikTok, получает UID и сохраняет выдачу в D1. При выдаче проверяется владение подтверждённым ключом UID создателя. Остальные клиенты получают назначение через `/badges`; интервалы обновления приложения — до двух минут. Таблица `badge_awards` создаётся схемой `server/cloudflare/schema.sql`.

## Протокол

- `GET /v1/profiles/<uid>`: оформление или 404, если оно не опубликовано.
- `GET /v1/profiles/<uid>/badge`: PNG значка.
- `POST /v1/verify`: проверка публичного описания TikTok и привязка ключа устройства.
- `POST /v1/publish`: запись для подтверждённого владельца.
- `POST /v1/remove`: скрытие оформления и удаление изображения из публичной записи.
- `POST /v1/badges/grant`: выдача значка сообщества подтверждённым создателем.
- `POST /v1/badges/revoke`: снятие выданного значка.
- `GET /badges`: публичные назначения значков вместе со встроенным значком создателя.

На телефоне генерируется случайный ключ 256 бит; сервер хранит только его SHA-256. На новом телефоне нужно подтвердить профиль заново; ключ старого телефона перестанет действовать. Значок PNG до 32 КиБ и 256×256, запрос до 64 КиБ. Проверяются диапазоны цветов, размеров и смещений. Ограничение: 20 запросов записи на IP за минуту.

## Проверка и ограничения

Java исходники компилируются в DEX для minSdk TikTok 47.2.41. Серверные тесты проверяют переходы страницы профиля, подтверждение владения, ограничения параметров, выдачу/снятие и отказ чужому ключу. TikTok может ограничить чтение публичной страницы; приложение повторит запрос позднее, но подтверждение невозможно без доступного публичного описания с кодом. Отображение на двух физических телефонах требует проверки после установки релиза.

Магазин плагинов отложен. Документация опубликована на GitHub: https://github.com/daniilsolovatulin-cyber/ttcuz-releases; также доступна на Cloudflare и в проекте.
