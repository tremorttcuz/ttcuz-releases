# Отчёты о сбоях — 0.3.5

Серверная часть подготовлена в архиве, но ещё не опубликована. Telegram-бот не подключён.

1. Обновить файлы Cloudflare Worker из server/cloudflare, включая worker.mjs и crashes.mjs.
2. Создать недостающие таблицы для отчётов и очереди командных плагинов: выполнить `migrations/0005-crash-reports.sql` и `migrations/0006-script-plugins.sql` в базе `ttcuz-profiles`, связанной как `PROFILES`.
3. Задать секрет CRASH_ADMIN_TOKEN на сервере. Его не нужно помещать в APK, репозиторий или браузерный URL.
4. Опубликовать Worker. Для чтения использовать GET /v1/admin/crashes с заголовком Authorization: Bearer <секрет>. Ответ содержит последние 100 отчётов. Доступ без секрета запрещён.
5. Пользователь включает «Отчёты о сбоях» в диагностике мода. После Java-сбоя и следующего запуска отчёт отправляется POST /v1/crashes. Успех — HTTP 202 и {"ok":true}.

Отчёт содержит случайный ID события, версию мода, Android SDK, время и классы/кадры технического стека. В нём нет имени пользователя, ID аккаунта, переписки, текста исключения, токенов, описания профиля и общего журнала. Сервер использует хеш адреса для ограничения частоты; сам IP в таблице отчётов не хранится. Хранение — до 30 дней, локальная очередь — до пяти событий.

Это сбор Java-исключений через стандартный UncaughtExceptionHandler с сохранением цепочки штатного обработчика. Он не заменяет полноценный сбор нативных падений и ANR; обработчик, полностью заменённый позже самим TikTok, также потребует отдельного подключения.

Автоматические уведомления добавим после появления бота. На этом этапе доступен закрытый серверный API отчётов.
