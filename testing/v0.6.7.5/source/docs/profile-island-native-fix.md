# Музыкальный островок: исправление нативного подключения в 0.6.7.3

Исходная версия: `ttcuz-project-v0_6_7_3-grid-corners.zip`.
Проверенная база APK: TikTok 47.2.41, `classes25.dex`, Android API 23.

## Почему островок отсутствовал

Мод ожидал `BaseContainerComponent.onViewCreated(View)`. Но настоящую шапку TikTok создаёт программно другим путём: `HeaderBaseContainerComponent.onCreate()` → `oq(ProfileComponentUIConfig)` → поле `LLLFFI` → `jq()`, которое передаёт шапку родительскому контейнеру. Это подтверждено новой разборкой APK, а не только тестовым примером. Старый хук не подключался к этому пути.

Кроме того, `ProfilePlatformViewModel.t43()` читает ID из параметров чужого профиля. В собственном профиле он может отсутствовать. Нативный `b43()` возвращает текущего пользователя для своего профиля и загруженного пользователя для чужого. Теперь при пустом `t43()` мод читает `b43().getUid()`.

## Исправлено

- Добавлен хук после создания реального контейнера шапки. Он обслуживает обычные и V2-компоненты через общий родительский класс.
- Привязка использует `LLLFFI`, а не случайный корень экрана.
- Добавлено чтение пользователя собственного профиля. Пустой или неправильный ID не подменяется текущим аккаунтом.
- Сборка требует наличия нового хука и проверяет, что его Java-метод есть в DEX мода.
- Старый совместимый DEX-кэш не используется для затронутого контейнера. Обычный кэш автоматически получает новый ключ после изменения правил.
- В журнале мода появляется строка `music profile hook`, когда шапка подключена.
- `VERSION`, `version.json` и встроенный `Version.MOD` согласованы на 0.6.7.3. В исходном архиве были разные номера 0.6.6.1 и 0.6.6.2.

Островок по-прежнему требует включённого отображения музыки в профиле. Чужая музыка показывается только при разрешённой публикации. Лента, фон приложения, скрытые и предварительно загруженные профили исключаются. Изменения скруглений сетки и антивыгорания из исходного архива сохранены.

## Проверка

- На коде исходного архива воспроизведена ошибка: настоящий контейнер с пользователем собственного профиля не определяется при пустом `t43()`.
- Исправленный код проходит эту проверку, включая создание до прикрепления окна, показ после прикрепления, смену пользователя, чужой закрытый профиль и возвращение из фона.
- Из APK заново извлечены восемь классов профиля. Подтверждены наследование компонентов, создание шапки и методы получения пользователя.
- Полный исходный `classes25.dex` разобран, исправлен штатным патчером, собран для API 23 и повторно разобран. Новый вызов сохранился: `native profile header create x1`.
- Весь Java-код мода скомпилирован в DEX; все обязательные методы переписывания найдены.
- Пройдено 237 автоматических проверок проекта.

В архиве лежит проект для сборки, а не готовый APK. Для применения нужен APK, собранный из этой папки `ttcuz-project-v0.6.7.3`, с тем же ключом подписи, который использовался для установленного мода. Копирование ZIP не изменяет уже установленное приложение. На физическом Android-устройстве эта версия пока не проверена.
