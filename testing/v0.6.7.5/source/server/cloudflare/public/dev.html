Что внутри .ctt

Это zip ровно из трёх файлов: manifest.json, classes.dex, icon.png (необязательно). Любые другие файлы отклоняются.

Как работает проверка

Проверка смотрит на то, что плагин вызывает, а не на слова в строках. Три исхода:

Что найдено
✗ блокRuntime.exec, ProcessBuilder, System.load*, DexClassLoader, native-методы, SMS, установка приложений, сервис доступности, права администратора. Также рефлексия к java.lang.Runtime или dalvik.system.*ClassLoader, заданная строкой.
✗ блокобфускация (имена из 1–2 букв, нет SourceFile); длинные base64-строки, которые не являются целой PNG/JPEG/WebP-картинкой
⚠ reviewрефлексия к стороннему классу или без читаемых имён; ссылка по http://; обращение к IP-адресу; сокращатель ссылок; длинная случайная строка. Плагин публикуется, но помечен «требует внимания».
✓ okСеть, файлы, рефлексия к API самого приложения (cat.narezany.margyt.*), картинки внутри кода. Показываются в карточке как «Умеет: …» вместе со списком доменов.

Проверка не антивирус: она ловит сокрытие и опасные примитивы и честно показывает возможности.

Частые ошибки

«Закодированная строка похожа на скрытый код» — раньше срабатывало на встроенные картинки. Теперь картинки проходят; если ошибка осталась, строка не декодируется в PNG/JPEG/WebP целиком.

Плагин не виден в магазине — он не прошёл проверку при выдаче. Причина пишется в лог сервера: [plugins] скрыт <id>: …

Проверить локально

cd server
python3 -c "import plugin_audit as a;r=a.analyze_package(open('my.ctt','rb').read());print(r['verdict'],r['capabilities'],r['domains'],r['notes'])"

JSON-скрипты (без кода)

Схема schema:1, до 8 КБ, до 16 команд (message, copy, window), имена по UID и цвета #RRGGBB. Отправка: POST /plugins/scripts/submit, после ручного одобрения попадает в /plugins/scripts.
